Capitulo 9

Aprendizaje no supervisado serio: clustering como hipótesis y no como verdad revelada

El aprendizaje no supervisado suele producir un entusiasmo desproporcionado. La razón es psicológica: cuando un algoritmo agrupa datos sin que nadie le haya dado etiquetas, parece que está “descubriendo la estructura oculta del mundo”. Esa intuición es peligrosa. Lo que realmente hace el algoritmo es optimizar cierto criterio geométrico o estadístico dentro de una representación concreta. No descubre esencia; propone una estructura bajo ciertos supuestos.

9.1 Qué problema resuelve realmente el clustering

Cuando clusterizas, normalmente intentas comprimir una nube compleja de observaciones en un conjunto pequeño de perfiles. Eso puede ser útil para:

  • Exploración inicial.
  • Segmentación operativa.
  • Diseño de campañas diferenciadas.
  • Generación de hipótesis.
  • Resumen visual o descriptivo.

Lo que no debes hacer es tratar los clusters como si fueran clases reales del negocio descubiertas automáticamente. El algoritmo no entiende causalidad, valor, costo ni semántica organizacional. Solo entiende la geometría del espacio de features que tú le diste.

9.2 Por qué la representación manda sobre el resultado

En aprendizaje supervisado, el target ofrece una referencia externa. En clustering, no. Eso significa que la elección de variables, escalado, transformaciones y métricas de distancia influye muchísimo más en el resultado final. Si clusterizas clientes con gasto total sin transformar una cola extremadamente sesgada, probablemente el cluster “premium” domine la estructura. Si escalas mal, una sola variable puede imponer toda la segmentación.

Por eso clustering es tanto una decisión de representación como una decisión algorítmica.

9.3 K-means entendido de forma útil

K-means busca centroides que minimizan la suma de distancias cuadráticas dentro de cada grupo. Lo importante no es memorizar la función objetivo, sino entender sus implicaciones:

  • Favorece clusters relativamente compactos y aproximadamente esféricos.
  • Es sensible a outliers.
  • Depende de escala.
  • Te obliga a elegir k.

Eso ya te dice cuándo confiar más o menos en él.

9.4 Segmentación accionable vs segmentación ornamental

La única segmentación que realmente vale algo es la que habilita acciones distintas. Si terminas con cuatro clusters bellamente coloreados pero no puedes decir qué harías distinto con cada uno, entonces no construiste una segmentación útil; construiste una visualización sofisticada.

Regla práctica: si no puedes escribir una acción concreta por cluster, todavía no has terminado el trabajo.

9.5 Tutorial completo: segmentación RFM paso a paso

Vamos a construir una segmentación de clientes con variables RFM: recency, frequency, monetary.

Paso 1. Construcción de variables

fecha_ref = compras["fecha"].max()

rfm = compras.groupby("cliente_id").agg(
    recency=("fecha", lambda s: (fecha_ref - s.max()).days),
    frequency=("orden_id", "nunique"),
    monetary=("monto", "sum")
).reset_index()

Estas tres variables son simples, pero muy poderosas. Resumen recencia, intensidad y valor económico.

Paso 2. Inspección de distribución

No saltes directamente a clusterizar. Mira antes la forma de las variables. Monetary suele ser muy sesgada. Frequency puede tener cola larga. Recency puede tener muchos valores concentrados.

print(rfm[["recency", "frequency", "monetary"]].describe())

Si monetary es extremadamente sesgada, podría convenir una transformación logarítmica:

import numpy as np
rfm["monetary_log"] = np.log1p(rfm["monetary"])

Paso 3. Escalado

from sklearn.preprocessing import StandardScaler

X = rfm[["recency", "frequency", "monetary_log"]].copy()
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)

El escalado es indispensable aquí porque las unidades son distintas y k-means es sensible a la escala.

Paso 4. Elegir varios valores de k

from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score

rows = []
for k in range(2, 8):
    model = KMeans(n_clusters=k, random_state=42, n_init=10)
    labels = model.fit_predict(X_scaled)
    rows.append({
        "k": k,
        "inercia": model.inertia_,
        "silhouette": silhouette_score(X_scaled, labels)
    })

print(pd.DataFrame(rows))

No tomes el silhouette score como verdad absoluta. Te orienta, pero la decisión final también depende de interpretabilidad y utilidad operativa.

Paso 5. Ajustar modelo final y perfilar clusters

kmeans = KMeans(n_clusters=4, random_state=42, n_init=10)
rfm["cluster"] = kmeans.fit_predict(X_scaled)

perfil = rfm.groupby("cluster").agg(
    clientes=("cliente_id", "count"),
    recency_med=("recency", "median"),
    frequency_med=("frequency", "median"),
    monetary_med=("monetary", "median")
)
print(perfil)

Aquí empieza lo realmente importante: interpretación. Supón que encuentras algo como esto:

  • Cluster A: alta recency, baja frequency, bajo monetary.
  • Cluster B: baja recency, alta frequency, alto monetary.
  • Cluster C: baja recency, media frequency, alto monetary.
  • Cluster D: recency media, baja frequency, ticket alto pero poca repetición.

Traducción posible:

  • A: dormidos o en riesgo.
  • B: fieles premium.
  • C: buenos clientes recientes pero quizá menos intensos.
  • D: compradores esporádicos de alto valor.

Ahora sí puedes pensar acciones distintas: retención, upsell, beneficios VIP o reactivación.

9.6 DBSCAN y clustering jerárquico

No todo clustering debe empezar o terminar en k-means. DBSCAN puede ser útil cuando esperas densidades locales y ruido. El clustering jerárquico puede ayudar a explorar estructura multinivel. Pero la pregunta sigue siendo la misma: ¿la estructura encontrada se traduce en hipótesis o acciones útiles?

Capitulo 10

Representaciones y reducción de dimensionalidad: cómo comprimir sin mentirte

Cuando la dimensión crece, el espacio se vuelve más extraño y más difícil de visualizar. Reducción de dimensionalidad aparece entonces como una herramienta para compresión, visualización y representación. Pero también aquí hay una fuente frecuente de superficialidad: muchos estudiantes confunden “se ve bonito en 2D” con “ya entendí la estructura del problema”. No es lo mismo.

10.1 PCA: qué hace y qué no hace

PCA busca direcciones lineales del espacio que capturen máxima varianza. Eso significa que comprime información de forma eficiente si la estructura relevante es aproximadamente lineal y si la varianza alta coincide con información útil. Pero no garantiza preservar la información más relevante para el objetivo de negocio ni para una tarea supervisada posterior.

10.2 Interpretación correcta de componentes

Una componente principal es una combinación lineal de variables originales. A veces tiene interpretación clara. A veces no. Si fuerzas narrativa donde no la hay, terminarás contando una historia falsa. PCA es valioso, pero exige humildad interpretativa.

10.3 Tutorial: PCA en datos de clientes o sensores

from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler

features = df[["x1", "x2", "x3", "x4", "x5"]]
X_scaled = StandardScaler().fit_transform(features)

pca = PCA(n_components=2)
X_pca = pca.fit_transform(X_scaled)

print("varianza explicada:", pca.explained_variance_ratio_)

La primera lectura útil es: cuánta varianza capturan las primeras componentes. La segunda es mirar las cargas:

loadings = pd.DataFrame(
    pca.components_.T,
    index=features.columns,
    columns=["PC1", "PC2"]
)
print(loadings)

Ahora sí puedes preguntar qué variables empujan cada componente. Pero recuerda: esto no prueba causalidad ni garantiza interpretabilidad semántica completa.

10.4 Embeddings y representaciones aprendidas

En problemas modernos, especialmente texto, imagen o recomendación, muchas veces ya no trabajas solo con variables manuales. Trabajas con representaciones aprendidas: embeddings. La idea profunda detrás de un embedding es traducir objetos complejos a vectores donde la geometría del espacio capture parte de la semántica o de la similitud funcional.

Esto abre la puerta a sistemas poderosos, pero también a nuevos riesgos: creer que porque tienes un embedding ya entendiste el fenómeno. No. Tienes una representación útil para ciertas tareas, no necesariamente una explicación del dominio.

10.5 Autoencoders y compresión no lineal

Cuando PCA es demasiado limitado, entran compresores no lineales como autoencoders. La intuición es simple: entrenas una red para pasar por un cuello de botella y reconstruir la entrada. Ese cuello de botella fuerza una representación comprimida. Es una idea poderosa, pero mucho más costosa y frágil que PCA. No debe usarse por prestigio sino por necesidad.

Capitulo 11

Interpretabilidad y fairness en profundidad: revisar el modelo como sistema socio-técnico

Interpretar un modelo no consiste en producir un gráfico y dar por cerrada la discusión. Interpretar significa entender qué señales usa el sistema, por qué las usa, qué limitaciones tiene esa lógica y qué riesgos emergen cuando un modelo se inserta en decisiones humanas, reglas organizacionales y poblaciones heterogéneas. En otras palabras: interpretar es evaluar el comportamiento del modelo dentro del mundo, no solo dentro del notebook.

11.1 Interpretabilidad global vs local

La interpretación global intenta describir qué patrones generales usa el modelo. La interpretación local intenta explicar por qué un caso concreto recibió un score particular. Ambas son importantes y ninguna reemplaza a la otra.

  • Global: qué features pesan más, qué interacciones dominan, qué zonas del espacio son más sensibles.
  • Local: por qué este cliente, esta transacción o este paciente recibió esta salida.

En sistemas operativos, la interpretación local importa mucho cuando necesitas auditar decisiones individuales. La global importa para revisar si el modelo está aprendiendo algo razonable en conjunto.

11.2 La trampa de confundir importancia con causalidad

Si una feature aparece como importante, eso no demuestra que sea una causa del resultado. Solo indica que el modelo la encuentra útil para predecir en ese contexto. Una variable puede ser importante porque resume un proceso histórico sesgado, porque actúa como proxy de otra más sensible o porque captura una correlación temporal espuria. La interpretación correcta debe mantener esa cautela.

11.3 Fairness: por qué el agregado es insuficiente

Una métrica global puede verse bien y aun así ocultar daños serios en un grupo concreto. Esto ocurre porque el rendimiento promedio puede esconder distribuciones de error muy desiguales. Si un score de riesgo genera muchos más falsos positivos en cierto grupo, las consecuencias humanas y operativas pueden ser muy distintas aunque la métrica total parezca aceptable.

Por eso la revisión por segmentos no es opcional en sistemas sensibles.

11.4 Tutorial: revisión de errores por grupo

eval_df = X_valid.copy()
eval_df["y_true"] = y_valid.values
eval_df["score"] = valid_proba
eval_df["pred"] = (eval_df["score"] >= 0.4).astype(int)

report = eval_df.groupby("segmento").agg(
    positivos_reales=("y_true", "mean"),
    positivos_predichos=("pred", "mean"),
    score_promedio=("score", "mean")
)
print(report)

Esto es apenas el inicio. Lo importante es que luego calcules errores específicos por grupo: precisión, recall, falsos positivos, falsos negativos y calibración si aplica.

11.5 SHAP y herramientas similares

Herramientas como SHAP pueden ser útiles para estudiar contribuciones locales y globales. Pero hay dos errores recurrentes:

  • Tomar sus gráficos como verdad final.
  • Olvidar que explican el comportamiento del modelo, no la estructura causal del mundo.

Usa estas herramientas como instrumentos de inspección, no como sustitutos del razonamiento crítico.

11.6 Model cards y documentación disciplinada

Un sistema serio debería venir con una ficha clara que responda:

  • Qué problema resuelve.
  • Qué datos usa.
  • Qué población cubre y cuál no.
  • Qué métricas obtuvo globalmente y por grupo.
  • Qué riesgos y limitaciones tiene.
  • Qué usos están permitidos y cuáles no.

Si esta documentación falta, el riesgo de uso incorrecto aumenta mucho incluso si el modelo es técnicamente fuerte.

Capitulo 12

Deep learning con criterio: cuándo vale la pena, cómo empezar y qué errores evitar

Deep learning es potente, pero su prestigio hace que muchos lo usen como símbolo de sofisticación más que como herramienta adecuada. El criterio correcto no es “usar redes porque son modernas”, sino entender cuándo la representación manual empieza a quedarse corta y cuándo el problema realmente justifica el costo de datos, cómputo y complejidad.

12.1 Dónde suele brillar deep learning

  • Visión por computador.
  • Audio.
  • NLP y texto complejo.
  • Secuencias ricas y datos no estructurados.
  • Aprendizaje de representaciones cuando el feature engineering manual se vuelve insuficiente.

En cambio, en muchos problemas tabulares medianos, gradient boosting sigue siendo una referencia formidable.

12.2 Transfer learning: el verdadero punto de entrada moderno

La forma sensata de entrar hoy a deep learning rara vez es entrenar desde cero. Normalmente empiezas con modelos preentrenados y los adaptas. Esa es una de las grandes ventajas del ecosistema moderno: puedes apoyarte en representaciones ya aprendidas y concentrarte en la tarea específica.

12.3 Tutorial conceptual: clasificación de texto con embeddings + clasificador simple

Una forma muy buena de entrar en este mundo sin saltar de golpe a arquitecturas complejas es usar embeddings de texto y un clasificador supervisado encima. Así aprendes representación y decisión por separado.

# Esquema conceptual
texts = [
    "no puedo iniciar sesion en la app",
    "quiero cambiar la direccion de envio",
    "me cobraron dos veces la orden"
]

# 1. Obtener embeddings con un modelo preentrenado
# 2. Convertir cada texto en un vector
# 3. Entrenar un clasificador simple sobre esos vectores

La lección aquí es fuerte: muchas veces el salto de calidad no viene de una arquitectura end-to-end gigante, sino de una representación mucho mejor de la entrada.

12.4 Cómo pensar una red neuronal desde cero

Una red neuronal puede entenderse como una función compuesta por múltiples transformaciones lineales y no lineales. La intuición central es que capas sucesivas permiten construir representaciones más abstractas. Pero no debes romantizar esa capacidad. También implica más parámetros, más riesgo de sobreajuste, más sensibilidad a datos y más complejidad de entrenamiento.

12.5 Costos ocultos

Antes de lanzarte a una solución profunda, debes pensar en:

  • Costo de etiquetado.
  • Costo de entrenamiento.
  • Latencia objetivo.
  • Capacidad de monitoreo.
  • Interpretabilidad requerida.
  • Disponibilidad de modelos preentrenados útiles.

En muchos casos, la respuesta correcta sigue siendo: “todavía no necesito deep learning”. Saber decir eso también es madurez técnica.

12.6 Tutorial mínimo con PyTorch: red para clasificación tabular como ejercicio conceptual

No porque sea la mejor opción en tabular, sino porque te ayuda a entender la mecánica de entrenamiento.

import torch
import torch.nn as nn

class MLP(nn.Module):
    def __init__(self, input_dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(input_dim, 64),
            nn.ReLU(),
            nn.Linear(64, 32),
            nn.ReLU(),
            nn.Linear(32, 1)
        )

    def forward(self, x):
        return self.net(x)

Lo importante aquí no es que esta sea la arquitectura ideal. Lo importante es entender qué hace una capa lineal, por qué aparece una activación no lineal y cómo el entrenamiento ajusta parámetros para reducir una pérdida.

12.7 Comparación honesta con modelos clásicos

Si pruebas una red, compárala honestamente con un baseline fuerte clásico. No des por hecho que ganarás. En datos tabulares, muchas veces no ganarás. Y si ganas por poco pero multiplicando complejidad, deberías preguntarte si el costo total vale la pena.

Regla práctica: deep learning no se justifica por prestigio técnico sino por estructura del dato y beneficio neto frente a alternativas más simples.
